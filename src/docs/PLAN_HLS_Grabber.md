# План работ HLS Grabber (к ТЗ v4)

## 0. Подвох ТЗ и правило построения плана

Раздел 10 ТЗ («Порядок работы агента») составлен как список из 8 «действий» — слоёв:
каркас → парсеры → браузер → загрузчики → FFmpeg → GUI → настройки → упаковка.
Это ловушка по трём причинам:

1. **«Действие» = «код написан», а не «работает».** Пройдя 8 пунктов формально,
   можно получить 8 отчётов и провал раздела 9 — acceptance-критериев, которые
   измеряют только рабочее приложение end-to-end. Мера готовности — раздел 9,
   не объём кода.
2. **Слои откладывают интеграцию на последний этап.** Самая опасная часть
   (перехват Playwright, повтор запроса с заголовками/cookie, FFmpeg внутри
   app-image без Java, драйвер Playwright в jpackage) оказывается в конце, когда
   менять уже поздно.
3. **Вертикальная нарезка absent.** ТЗ не содержит ни одного этапа, где
   «нажал Скачать → получил воспроизводимый .mp4» проверяется целиком.

Правила, по которым построен этот план:

- **Этап = рабочая вертикальная вертикаль с демонстрацией.** Каждый этап
  заканчивается проверяемым артефактом (CLI выдаёт mp4, GUI показывает строку,
  окно не зависает), а не «модуль написан».
- **Риски валидируются первыми (Phase 0).** Спайки — бросовый код, результат:
  GO/NO-GO по каждому критическому допущению. NO-GO = смена технологии,
  решение принимается до написания продукта.
- **Exit-check каждого этапа прописан заранее и проверяем человеком**,
  критерий привязан к разделу 9 ТЗ.
- **Трек-статус живёт в этом файле** (раздел 6): статус этапа меняет только
  закрывший exit-check.

## 1. Определение результата (якорь — раздел 9 ТЗ)

Готово = все пункты раздела 9 выполняются на чистой Windows:

- `mvn clean package` на JDK 21 без ошибок;
- jpackage app-image запускается **без установленной Java**;
- после выбора папки: окно (пустая верхняя секция с подсказкой + консоль),
  параллельно браузер;
- на тестовых HLS / DASH / MP4 источник появляется строкой (название, ссылка,
  кнопка «Скачать»);
- скачивание только по кнопке, прогресс в строке, на выходе **воспроизводимый .mp4**;
- live, DRM, потоки без 1080p пропускаются с записью в консоли;
- несколько «Скачать» — строго по очереди; «Отмена» чистит временные файлы;
- окно не зависает (сеть и FFmpeg вне Swing-потока);
- unit-тесты по списку раздела 9 (HLS, DASH, DRM, QualityFilter, Range-merge,
  FileNames).

## 3. Этапы работ (вертикальные срезы)

Каждый этап: **цель → артефакт → exit-check → тесты**. Exit-check проверяется
человеком, статус в разделе 6 меняется только после него.

### Этап 1. Каркас + ядро pipeline в CLI (без GUI)
- **Цель**: доказать путь «m3u8 → сегменты → AES-128 → FFmpeg → mp4» без браузера
  и GUI, на заготовленных манифестах.
- **Артефакт**: исправленный `pom.xml` (Playwright, bytedeco ffmpeg
  windows-x86_64, shade-plugin; **Selenium и Jsoup выкинуть**); пакет
  `com.example.hlsgrabber` (`App`, каркас по разделу 7); CLI-драйвер: файл
  `main`-класса, принимающий путь к m3u8 + папку; парсеры HLS master/media,
  `KeyInfo`, `SegmentDownloader`, `Decryptor`, `FfmpegRunner`.
- **Exit-check**: CLI на заготовленном AES-128 HLS выдаёт воспроизводимый mp4;
  `mvn clean package` проходит; unit-тесты HLS (master, media, AES-128,
  EXT-X-MAP, byterange, относительные URL) зелёные.
- **Тесты**: HLS-парсеры, Decryptor (известный IV по sequence), FileNames.

### Этап 2. Браузер + sniffing + GUI: сквозная вертикаль
- **Цель**: первая реальная сквозная линия — браузер, перехват, строка в GUI,
  кнопка, mp4.
- **Артефакт**: `BrowserLauncher` (headed, persistent profile `.profile`,
  каналы chrome → msedge → Chromium), `NetworkSniffer` (кандидаты .m3u8/.mpd/
  Content-Type, прямые MP4), `SourceRegistry`, GUI: `JSplitPane` 40/60,
  `SourceListPanel`, `SourceRowPanel` (типы states: Найдено/Скачивается/
  Готово/Ошибка), `LogPanel`, `SwingLogAppender`, `JFileChooser` + `%APPDATA%`.
- **Exit-check**: на тестовой странице с HLS строка появляется автоматически,
  «Скачать» запускает pipeline из этапа 1, в папке появляется mp4, консоль
  показывает полный путь (запуск браузера, манифест, сегменты, FFmpeg). Окно
  не зависает при 2000+ событий sniffing.
- **Тесты**: канонизация URL, детект кандидатов по Content-Type/URL.

### Этап 3. Фильтры: live, DRM, 1080p, дубликаты, MP4 Range
- **Цель**: все решения раздела 5 принимаются корректно и видны в консоли.
- **Артефакт**: `ManifestDetector`, `DrmDetector`, `QualityFilter`,
  Range-merge MP4, порог 1 МБ (`targetHeight`/`minSize` — settings, без UI).
- **Exit-check**: матрица заготовленных манифестов (live HLS без ENDLIST,
  dynamic MPD, SAMPLE-AES, Widevine MPD, master 720p/480p, master со
  1080p-вариантом, single-stream 1080, single-stream unknown) даёт в консоли
  ровно предсказанные пропуски/показ; MP4-Range-запросы схлопываются в одну
  запись с полным размером.
- **Тесты**: DrmDetector, QualityFilter (выбор max bandwidth среди 1080p),
  Range-merge.

### Этап 4. HLS: полный набор фич
- **Цель**: мастер-плейлисты, init-сегменты, byterange, отдельные аудиодорожки.
- **Артефакт**: `#EXT-X-MAP` первым, `#EXT-X-BYTERANGE`, `#EXT-X-MEDIA`
  (аудио муксируется), выбор 1080p-варианта из master, лучшая аудиодорожка.
- **Exit-check**: 4 тестовых HLS (master+media, fMP4, byterange,
  audio-трек) — 4 mp4, все воспроизводимые, аудио на месте.
- **Тесты**: EXT-X-MAP, EXT-X-BYTERANGE, EXT-X-MEDIA, резолв относительных URL.

### Этап 5. DASH
- **Цель**: DASH-манифесты тех же двух типов (static+segmentlist/template)
  дают mp4.
- **Артефакт**: `MpdParser` (DOM/StAX), `Representation`, `SegmentResolver`:
  `$Number$/$Time$/$RepresentationID$/$Bandwidth$`, SegmentTimeline, SegmentList,
  SegmentBase, BaseURL, несколько Period; выбор Representation (видео 1080p,
  аудио); init + сегменты, видео+аудио муксинг.
- **Exit-check**: 2 тестовых MPD → mp4; DASH-тесты зелёные.
- **Тесты**: SegmentTemplate, SegmentTimeline, BaseURL, Period.

### Этап 6. Очередь, отмена, надёжность, закрытие окна
- **Цель**: поведение по разделам 3, 4.1, 6.1 — всё штатное и краевое.
- **Артефакт**: `DownloadQueue` (один исполнитель, строгая очередь),
  `RetryPolicy` (3 попытки, экспоненциально, докачка), параллельность сегментов
  до 6, отмена (останов HTTP и FFmpeg, чистка temp), состояния строки
  (В очереди/Скачивается/Отмена/Повторить/Открыть папку), закрытие окна с
  подтверждением, реакция на закрытие браузером, имена файлов
  (санитизация, лимит пути, ` (1)`), `.tmp/<id>/`, `.part` для MP4.
- **Exit-check**: три «Скачать» подряд — строго по очереди; «Отмена» на
  середине — temp пусто, FFmpeg убит; ошибка загрузки — temp сохранён, причина
  в консоли, «Повторить»; закрытие окна при загрузке — диалог, корректный
  exit; браузер закрыт пользователем — сообщение, загрузка дожидается.
- **Тесты**: FileNames (конфликты, лимит), RetryPolicy.

### Этап 7. Упаковка и чистая Windows
- **Цель**: jpackage app-image, запуск без Java.
- **Артефакт**: shade fat jar, jlink-рантайм, jpackage `--type app-image`
  (без `--win-console`), Playwright driver + браузеры внутри пакета (по
  решению R3), `.profile` и settings в `%APPDATA%`.
- **Exit-check**: на ВМ/чистой Windows без Java: app-image стартует, выбор
  папки, браузер channel: chrome, сквозной тест этапа 2 (строка → mp4),
  FFmpeg из этапа 1 работает внутри app-image.
- **Тесты**: ручной прогон на чистой машине; список проверок в
  `docs/acceptance.md`.

### Этап 8. Приёмка по разделу 9
- **Цель**: полный прогон критериев раздела 9 на тестовых сайтах.
- **Артефакт**: протокол приёмки — каждый критерий: проверяющий, результат,
  скрин/лог; `docs/tests.md` — список тестовых HLS/DASH/MP4 и ожидаемое
  поведение.
- **Exit-check**: все пункты раздела 9 — PASS. Любый FAIL = возврат к этапу
  с причиной, статус в разделе 6.

## 4. Инварианты (действуют на всех этапах)

- GUI-изменения только через `SwingUtilities.invokeLater`; сеть и FFmpeg
  **вне** Swing-потока и **вне** потоков Playwright-обработчиков (обработчик:
  снять данные → в очередь → вернуться).
- Один поток-исполнитель загрузок; очередь строгая, последовательная.
- Временное: `.tmp/<id задачи>/` сегменты; итог — корень выбранной папки;
  при успехе temp удаляется, при ошибке — сохраняется.
- Имена: `<заголовок страницы>.mp4`, санитизация Windows-символов, лимит
  длины пути, конфликт → ` (1)`, ` (2)`.
- Заголовки при повторе: Referer, Origin, UA из перехваченного запроса,
  Cookie из `context.cookies(url)`; относительные URL резолвятся от манифеста;
  query-токены сохраняются.
- Лог: SLF4J + Logback, файл `<папка>/hlsgrabber.log` + SwingLogAppender;
  формат `[HH:mm:ss] LEVEL сообщение`; буфер ~5000 строк; консоль — весь лог.
- Настройки: `targetHeight=1080`, `minSize≈1 МБ`, параллельность сегментов ≤6
  — в settings, без UI; путь загрузок в `%APPDATA%`.
- Пакет `com.example.hlsgrabber`; шаблонный `org.example.Main` удалить.
- Не делать: обход DRM, live, автологин/капча, веб-интерфейс, параллельные
  загрузки, WiX-установщик.
