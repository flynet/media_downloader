# ТЗ (версия 4): Java-приложение для перехвата и скачивания HLS / DASH / MP4-видео

## 1. Цель

Windows-приложение (.exe) на Java 21 + Maven.

После запуска пользователь выбирает папку для загрузок, открывается управляемый браузер и окно программы из двух секций (найденные видео сверху, консоль снизу). Пользователь сам заходит на сайт и запускает видео. Приложение перехватывает сетевые запросы браузера, находит:

- HLS-плейлисты (`.m3u8`),
- MPEG-DASH манифесты (`.mpd`),
- прямые ссылки на MP4,

показывает найденное в верхней секции и скачивает **только после нажатия кнопки «Скачать»** у конкретного видео. Сегменты кладутся во временную папку и склеиваются FFmpeg в один файл.

Принцип: браузер уже умеет получать и расшифровывать (AES-128) поток, значит программа делает то же самое по тем же URL и ключам. Исключение: DRM (Widevine / PlayReady / FairPlay), там ключи недоступны, такие видео пропускаются.

## 2. Технический стек

| Компонент | Решение |
|---|---|
| Язык / сборка | Java 21, Maven, один модуль |
| Перехват сети | **Playwright for Java** (`com.microsoft.playwright`): `context.onRequest` / `context.onResponse` на уровне контекста, чтобы видеть все вкладки и popup. Selenium и CDP не используются |
| Браузер | Порядок попыток: `channel: "chrome"` → `channel: "msedge"` → Chromium, который Playwright скачивает сам при первом запуске. Режим headed, persistent context с профилем в `<папка>/.profile`. Если используется Chromium от Playwright, в лог пишется предупреждение: часть сайтов может не проигрывать H.264/AAC |
| FFmpeg | Зависимость `org.bytedeco:ffmpeg` + `org.bytedeco:javacpp`, **только классификатор `windows-x86_64`** (не `ffmpeg-platform`, он весит сотни МБ). Путь к бинарнику через `Loader.load(org.bytedeco.ffmpeg.ffmpeg.class)`, запуск через `ProcessBuilder` |
| HTTP | `java.net.http.HttpClient` |
| DASH-парсер | Стандартный DOM/StAX, внешняя библиотека не нужна |
| Логи | SLF4J + Logback. Два appender'а: файл `<папка>/hlsgrabber.log` и кастомный `SwingLogAppender`, который пишет в консоль окна |
| GUI | Swing (раздел 4) |
| Упаковка | `maven-shade-plugin` (fat jar), затем `jpackage` (JDK 21) в `--type app-image` с jlink-рантаймом. Флаг `--win-console` не использовать (консоль есть внутри GUI). Установочный .exe (WiX) не нужен |

## 3. Сценарий работы

1. Запуск программы. Диалог `JFileChooser` для выбора папки загрузок. Отмена завершает программу. Выбранный путь запоминается в `%APPDATA%`.
2. Открывается главное окно и параллельно браузер. В выбранной папке создаётся `.tmp/<id задачи>/` для сегментов. Готовые файлы лежат в корне выбранной папки.
3. Пользователь заходит на сайт и запускает видео. `NetworkSniffer` анализирует трафик. Подходящие источники (прошедшие фильтры, раздел 5) появляются строками в верхней секции окна.
4. Пользователь нажимает «Скачать» в нужной строке. Задача ставится в очередь, прогресс отображается внутри этой строки.
5. Загрузки **строго последовательные** (один поток-исполнитель). Если нажато «Скачать» у нескольких видео, они выполняются по очереди.
6. После склейки временная папка задачи удаляется, строка переходит в состояние «Готово». При ошибке временные файлы сохраняются, причина пишется в лог и консоль.
7. Закрытие окна: если идёт загрузка, спросить подтверждение. После согласия отменить загрузку, закрыть браузер, завершить программу. Если пользователь закрыл браузер, программа сообщает об этом в консоли и ждёт завершения текущей загрузки (или предлагает прервать).

## 4. GUI (Swing, одно окно из двух секций)

Окно делится на две части через `JSplitPane` (вертикальное разделение, пользователь может двигать разделитель; по умолчанию примерно 40% сверху и 60% снизу).

### 4.1. Верхняя секция: найденные видео

- При запуске список пустой. По центру серый текст-подсказка: «Видео пока не найдены. Откройте сайт в браузере и запустите видео».
- Когда `NetworkSniffer` находит подходящий источник, в список добавляется строка. Список прокручиваемый (`JScrollPane`), новые строки добавляются вниз.
- Каждая строка содержит:
  - тип источника (метка HLS / DASH / MP4);
  - название (заголовок страницы, на которой найдено видео);
  - ссылку (URL, обрезанный по ширине, полный в tooltip, по правому клику пункт «Копировать ссылку»);
  - разрешение и длительность или размер, если известны;
  - кнопку **«Скачать»** справа.
- Состояния строки:
  - **Найдено**: активная кнопка «Скачать».
  - **В очереди**: кнопка заблокирована, подпись «В очереди» (если уже идёт другая загрузка).
  - **Скачивается**: вместо кнопки прогресс-бар со скоростью, процентом, «сегменты X из Y», этапом (скачивание / расшифровка / склейка) и кнопка «Отмена».
  - **Готово**: подпись «Готово» и кнопка «Открыть папку».
  - **Ошибка**: красная подпись и кнопка «Повторить», подробности в консоли.
- Нажатие «Скачать» только ставит задачу в очередь.
- Реализация: панель с `BoxLayout` (по вертикали), в ней отдельный `JPanel` (`SourceRowPanel`) на каждую строку. Не использовать `JTable` с кастомными рендерерами кнопок: строк немного, а панели проще и надёжнее.
- Отдельного общего прогресс-бара между секциями нет, прогресс живёт внутри строки.

### 4.2. Нижняя секция: консоль

- `JTextArea` в `JScrollPane`, только чтение, моноширинный шрифт.
- Автопрокрутка вниз (отключается, если пользователь прокрутил вверх, включается снова при прокрутке в конец).
- Буфер ограничен ~5000 строк (старые удаляются).
- Сюда идёт весь лог: запуск браузера, найденные манифесты, причины пропуска (live, DRM, нет 1080p), сегменты, повторы, вызовы FFmpeg, ошибки.
- Формат строки: `[12:34:56] INFO  Найден HLS-поток 1080p: https://...`
- Над консолью две маленькие кнопки: «Очистить» и «Открыть папку загрузки».

### 4.3. Общие правила GUI

- Все изменения GUI только через `SwingUtilities.invokeLater`.
- Сетевые операции и FFmpeg не выполняются ни в потоке Swing, ни в потоке обработчиков Playwright (обработчики только кладут события в очередь и быстро возвращаются).
- Заголовок окна: «HLS Grabber: папка: `<путь>`».

## 5. Обнаружение и фильтрация источников

### 5.1. Кандидаты

**HLS / DASH.** Запрос считается кандидатом, если:
- URL содержит `.m3u8` или `.mpd`, **или**
- Content-Type один из: `application/vnd.apple.mpegurl`, `application/x-mpegURL`, `audio/mpegurl`, `application/dash+xml`.

Тело ответа читается и парсится.

**Прямые MP4.** Content-Type `video/mp4` или URL оканчивается на `.mp4` (до query).
- Браузер часто запрашивает такие файлы кусками через `Range`, поэтому запросы с одним и тем же нормализованным URL объединяются в одну запись.
- Полный размер берётся из `Content-Range` (`bytes 0-1/12345678`) или `Content-Length`.
- Файлы меньше ~1 МБ (настраивается) отбрасываются как не видео.
- Фрагменты fMP4-сегментов (`.m4s`, `.mp4`, принадлежащие уже найденному HLS/DASH-манифесту) в список не попадают.

### 5.2. Фильтры (в порядке применения)

1. **Live.** HLS без `#EXT-X-ENDLIST` и DASH с `type="dynamic"` пропускаются, причина в лог.
2. **DRM.** Пропускается, если:
   - `#EXT-X-KEY` с методом, отличным от `NONE` и `AES-128` (SAMPLE-AES и т. п.);
   - в MPD есть `ContentProtection` с Widevine, PlayReady или FairPlay.

   Сообщение в консоль: «Контент защищён DRM, скачивание невозможно».
3. **Качество 1080p.** Нас интересует только высота 1080.
   - Для master-плейлиста и MPD источник показывается, только если есть вариант с `height == 1080`. Выбирается вариант с максимальным bandwidth среди 1080p и лучшая аудиодорожка.
   - Если 1080p нет, источник не показывается, в консоль пишется: «Найден поток без 1080p: пропущен (доступно: 720p, 480p)».
   - Media playlist без вариантов (один поток) показывается, если разрешение 1080 или не определяется (в строке «неизвестно»).
   - Для прямых MP4 разрешение определяется через FFmpeg (`ffmpeg -i`, с заголовками по возможности). При неудаче показывается «неизвестно», файл остаётся в списке.
   - Порог вынесен в настройки (`targetHeight`, по умолчанию 1080), без UI.
4. **Дубликаты.** По нормализованному URL (без токенов в query, если очевидно, что они меняются, иначе по полному URL).

## 6. Скачивание

### 6.1. Общее
- **Заголовки.** Для манифестов, сегментов и ключей используются `Referer`, `Origin`, `User-Agent` из перехваченного запроса и `Cookie` из `context.cookies(url)`.
- **URL.** Относительные пути резолвятся от URL манифеста. Query-параметры (токены, подписи) сохраняются.
- **Параллельность внутри одной загрузки:** до 6 потоков на сегменты (настройка).
- **Повторы:** 3 попытки с экспоненциальной паузой. Уже скачанные сегменты при повторе пропускаются (докачка).
- **Имя файла:** `<заголовок страницы>.mp4`. Запрещённые символы Windows заменяются, длина обрезается (с учётом лимита пути). При конфликте имён суффикс ` (1)`, ` (2)` и т. д.
- **Отмена:** по кнопке «Отмена» загрузка прерывается, активные HTTP-запросы и процесс FFmpeg останавливаются, временные файлы задачи удаляются.

### 6.2. HLS
- Master и media playlists.
- `#EXT-X-MAP` (init-сегмент fMP4) скачивается первым.
- `#EXT-X-BYTERANGE`.
- `#EXT-X-MEDIA` (отдельная аудиодорожка скачивается и муксируется; субтитры не обязательны).
- **AES-128** (`#EXT-X-KEY:METHOD=AES-128`): скачать ключ, расшифровать сегменты в Java через `AES/CBC/PKCS5Padding`. IV берётся из атрибута `IV` или вычисляется из media sequence number сегмента.

### 6.3. DASH
- `SegmentTemplate` (`$Number$`, `$Time$`, `$RepresentationID$`, `$Bandwidth$`), `SegmentTimeline`, `SegmentList`, `SegmentBase`, `BaseURL`, несколько Period.
- Для видео и аудио выбирается лучший Representation (видео по условию 1080p).
- Init-сегмент + сегменты склеиваются по порядку, затем видео и аудио муксируются FFmpeg.

### 6.4. Прямой MP4
- Скачивание одним потоком. При поддержке `Accept-Ranges` докачка с места обрыва.
- Склейка не нужна: после завершения `.part`-файл переименовывается в итоговое имя.

### 6.5. Склейка (FFmpeg)
- Без перекодирования: `-c copy`.
- Видео и аудио отдельными дорожками через `-map`.
- При необходимости `-bsf:a aac_adtstoasc` (ADTS AAC в MP4).
- Способ (concat-список локальных файлов или переписанный локальный m3u8) выбирает агент, главное, чтобы работало надёжно.
- Вывод FFmpeg парсится для прогресса (этап «склейка») и пишется в лог.

## 8. Вне рамок (не делать)

- Обход DRM и любых защит контента.
- Live-трансляции.
- Автоматический логин, обход капчи и подписок (всё делает пользователь вручную в браузере).
- Веб-интерфейс.
- Параллельные загрузки нескольких видео (только последовательная очередь).
- Установочный .exe через WiX.

## 9. Критерии приёмки

- `mvn clean package` проходит на JDK 21 без ошибок.
- jpackage-сборка запускается на чистой Windows без установленной Java.
- При старте после выбора папки открывается окно: верхняя секция пустая с подсказкой, нижняя секция показывает консоль, параллельно открывается браузер.
- На открытых тестовых HLS, DASH и прямом MP4 источник автоматически появляется строкой в верхней секции с названием, ссылкой и кнопкой «Скачать».
- Скачивание стартует только после нажатия кнопки. Строка переходит в состояние загрузки с прогресс-баром, на выходе воспроизводимый .mp4.
- Строка найденного источника показывает список доступных качеств (например «Найдено · качества: 1080p, 720p, 480p»).
- Скачивается одна линка максимального доступного качества в пределах настройки targetHeight (cap); если все варианты выше cap — берётся общий максимум.
- Live и DRM пропускаются с понятной записью в консоли.
- Несколько нажатых «Скачать» выполняются строго по очереди.
- «Отмена» корректно останавливает загрузку и чистит временные файлы.
- Окно не «зависает» во время загрузки (сеть и FFmpeg вне потока Swing).
- Unit-тесты:
  - HLS: master, media, AES-128, fMP4 (`EXT-X-MAP`), byterange, относительные URL;
  - DASH: SegmentTemplate, SegmentTimeline, BaseURL;
  - DrmDetector, QualityFilter;
  - объединение Range-запросов MP4;
  - FileNames (санитизация, конфликты имён).

## 10. Порядок работы агента

1. Каркас проекта и `pom.xml` (Playwright, bytedeco ffmpeg `windows-x86_64`, Logback, JUnit 5, shade-plugin).
2. Парсеры HLS и DASH, `QualityFilter`, `DrmDetector` + unit-тесты.
3. `BrowserLauncher` и `NetworkSniffer` (включая детект и объединение MP4).
4. Загрузчики, дешифрование, очередь, отмена.
5. `FfmpegRunner`.
6. Swing-окно: `JSplitPane`, список карточек с кнопками, консоль, `SwingLogAppender`.
7. Выбор папки, настройки (`%APPDATA%`), корректное закрытие.
8. Упаковка jpackage и проверка на чистой Windows.

## 11. Принятые допущения (можно изменить)

- Скачивается максимальное доступное качество в пределах cap-настройки targetHeight; потоки ниже cap не скрываются, список качеств виден в строке.
- Прогресс загрузки показывается внутри строки видео.
- У каждой загружающейся строки есть кнопка «Отмена».
- Chromium от Playwright используется только как запасной вариант, если нет Chrome/Edge.
